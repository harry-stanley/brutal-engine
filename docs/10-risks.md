# 10. Risks

Each risk has an owner action. Spikes retire risks with evidence. Their results are written back here (status column) or as ADRs.

| ID | Risk | Impact | Likelihood | Mitigation | Status |
|----|------|--------|------------|------------|--------|
| R1 | **macOS is not officially supported by BRUTAL.** MoltenVK and the Vulkan loader aren't bundled (`Brutal.Vulkan/ImportResolver.cs` has a TODO for it), and nobody upstream guarantees macOS behaviour | High: one of three platforms | High | We build, bundle and sign MoltenVK and the loader ourselves (`natives.yml`). No real Mac is available yet (Q6), so [ADR-0015](adr/0015-tested-platforms-windows-linux.md) makes macOS best-effort: from M1 on, CI doesn't build or test it, and nothing claims it works. Spike S1. Report macOS issues upstream with repros. **S1 (macOS runner):** a bundled loader + MoltenVK 1.4.2 works offscreen with validation, provided the engine preloads the loader and sets `VK_DRIVER_FILES` ([results](spikes/README.md#s1--s3-macos-on-githubs-macos-15-runner)). **CI in M0:** the `vulkan-smoke` job ran that setup (JIT and NativeAOT, validation on), with the pins and build scripts in `natives/macos-vulkan` | Accepted as unverified from M1 on ([ADR-0015](adr/0015-tested-platforms-windows-linux.md)). In M0, HelloWindow's NativeAOT publish also ran self-contained on the macOS runner, headless: the loader, MoltenVK and its ICD manifest sat next to the executable, with no `--vulkan-loader` and no `VK_DRIVER_FILES`, and its JIT build ran there with the bundled loader passed explicitly (#41). Open: macOS CI, windowed presentation, `.app` bundles, real GPUs |
| R2 | **No GPU on hosted CI runners**, so GPU code could be "tested" only on software drivers that differ from real hardware | High | Certain | Software Vulkan (lavapipe/SwiftShader) for every PR, real-GPU conformance runs on the reference machine recorded in each graphics PR (self-hosted nightly runners are the later target, not set up in M1), conformance suite with validation layers. **S3:** lavapipe + validation works on ubuntu-24.04, windows-2025 and (via MoltenVK on paravirtual Metal) macos-15 ([results](spikes/README.md)) | Mitigated |
| R3 | **Metal unavailable on GitHub macOS runners**, so no MoltenVK GPU tests on PRs | Medium | Medium | No self-hosted Mac exists, so a Metal-less runner would leave macOS rendering untested in CI. Resolving Q6 (a Mac mini runner or a cloud Mac) is the mitigation | **Resolved by S3:** the macos-15 runner exposes a paravirtual Metal device, and MoltenVK runs on it. It is good for correctness, not for GPU families or performance. The `vulkan-smoke` job used it in M0; since [ADR-0015](adr/0015-tested-platforms-windows-linux.md) CI runs nothing on macOS |
| R4 | **BRUTAL packages not fully NativeAOT/trim clean**, or other runtime surprises with published packages | High: release format | Low to medium | Spike S2. Report upstream. Pin known-good versions. As a last resort, JIT self-contained publish as a documented fallback for affected platforms. **S2:** 0 trim/AOT warnings on Windows for the paths exercised, but BRUTAL doesn't declare `IsAotCompatible`, so AOT smoke tests must cover every BRUTAL path we use | Mitigated for exercised paths |
| R5 | **Scope:** v1 includes every feature group (up to networking). This is a full commercial engine | High: schedule | High | Strict milestone order with a release per milestone. Later milestones can be cut from 1.0 into 1.x by an ADR without invalidating earlier work. No parallel half-finished subsystems | Accepted, managed |
| R6 | **BRUTAL API churn** (CalVer, pre-1.0 style evolution) breaks us | Medium | Medium | Central version pinning. BRUTAL bumps as dedicated PRs with full CI. Backend projects isolate binding usage, so churn stays local | Managed |
| R7 | **Complex-script text shaping** (HarfBuzz) not available through BRUTAL in a usable form | Medium: localisation quality | Medium | Spike S8 at the start of M3 (`Ahwoo.Brutal.Sdl.Ttf` HarfBuzz, or bundling HarfBuzz ourselves). Until resolved, document LTR-only support. **S8 research:** SDL3_ttf's internal HarfBuzz isn't exported, so the recommendation is our own HarfBuzz C bindings ([results](spikes/README.md#s8-complex-script-text-shaping-research-nothing-executed)) | Recommendation ready, ADR at M3 |
| R8 | **RakNet is unmaintained upstream**, a security and maintenance risk for a public engine | Medium | High (if chosen) | Spike S7 compares it with an in-house UDP transport. Either choice gets fuzzing and a security review | Open (S7) |
| R9 | **Name and trademark:** "BrutalEngine" uses Ahwoo's BRUTAL name. The licence grants copyright, not trademark, permission | Medium: rename cost grows over time | Unknown | The maintainer accepts the name for now (2026-11-25). Revisit before 1.0, when a rename becomes expensive | Accepted for now (Q5) |
| R10 | **BRUTAL licence duties for downstream games** (logo splash, credits, NOTICE) are easy for game developers to miss | Medium: legal exposure for users | Medium | Compliance on by default (splash, credits API, publish copies notices, test verifies). Documented prominently in the manual | Mitigated by design |
| R11 | **Single maintainer / reviewer bottleneck** | Medium | High | Small PRs, strong automation (CI gates do the mechanical review), design docs before big PRs so review is incremental | Managed |
| R12 | **Self-hosted runners on a public repo** could run malicious PR code | High: security | Low with controls | Never run self-hosted jobs on `pull_request`, ephemeral runners, unprivileged user (see [CI/CD](06-ci-cd-and-release.md#self-hosted-runners)) | Mitigated by design |
| R13 | **Audio decoding dependency** for compressed streaming (Vorbis/Opus) not provided by BRUTAL in a mixer-friendly form | Low to medium | Medium | Spike S6 at the start of M2: a managed decoder (licence-checked, AOT-checked) vs SDL3_mixer's decoders (`Ahwoo.Brutal.Sdl.Mixer`) vs bundling a C decoder. **S6 research:** SDL3_mixer (already shipped by BRUTAL) has Vorbis, FLAC and MP3 decoders usable without its mixer, but no Opus. **S6 prototype:** WAV, Ogg Vorbis, FLAC and MP3 decode from memory, and a looping Ogg stream plays through a headless mixer, with 0 managed bytes per call and identical output on Linux and Windows, JIT and NativeAOT ([results](spikes/README.md#s6-compressed-audio-decoding-prototype)) | **Resolved by [ADR-0017](adr/0017-audio-decoding.md):** SDL3_mixer as a decoder only, in `Audio.Sdl3` and the cook-time importer; no Opus in 0.3. macOS not run ([ADR-0015](adr/0015-tested-platforms-windows-linux.md)) |
| R14 | **Box2D cross-platform determinism** may not hold for our usage | Low to medium: affects networking design | Low to medium | Cross-OS determinism test from M3. If it fails, networking uses server authority without lockstep (already the plan) | Open |
| R15 | **Single GPU vendor on real hardware:** the only real GPU, on the reference machine, is an NVIDIA RTX 2070 SUPER, so AMD, Intel and Apple driver behaviour is checked only through software drivers and validation layers | Medium: vendor-specific bugs ship unnoticed | Medium | Strict validation layers plus conformance tests on lavapipe (Mesa). Community or beta testers on AMD and Intel before each release. Add hardware when possible (Q7) | Open |
| R16 | **BRUTAL binding gaps and dependencies:** normal Vulkan results thrown as exceptions (OUT_OF_DATE), needed APIs `internal`, `uint64` bound as `nint`, and a **.NET 11 preview** dependency (`Microsoft.Extensions.ObjectPool` 11.0.0-preview.5 via `Ahwoo.Brutal.Strings`) | Medium: correctness workarounds, and a pre-release package in a shipped engine | Certain (found in S1/S4) | Work around in backend projects only, each with a test and an upstream issue link, per [coding standards](07-coding-standards.md#native-interop-rules-engine-side). Report each gap upstream. **Correction:** `Ahwoo.Brutal.Vulkan` and `Ahwoo.Brutal.Vulkan.Abstractions` themselves depend on `Ahwoo.Brutal.Strings` (verified in their nuspecs), so any Vulkan-using assembly gets the preview package transitively, and it can't be pinned down to a .NET 10 GA version (NuGet forbids downgrading below a dependency's minimum). It also reaches `Platform.Sdl3` (`Ahwoo.Brutal.Sdl` -> `Ahwoo.Brutal.Logging` -> `Strings`), DebugOverlay (through `Ahwoo.Brutal.ImGui`) and the cook tool (through `Ahwoo.Brutal.Slang`). **[ADR-0011](adr/0011-brutal-objectpool-dependency.md)** accepts it from Platform.Sdl3 onward, not only in Graphics.Vulkan: assemblies that reference BRUTAL binding packages take it transitively, pinned centrally to the `11.0.0` GA release (the pin lands with the first engine project that references BRUTAL); Core, Platform, Graphics and World reference no package that brings it (BRUTAL's Memory, Collections and Concurrency don't); removed when BRUTAL depends on a GA version (upstream issue draft #2) | Preview dependency accepted by [ADR-0011](adr/0011-brutal-objectpool-dependency.md) (from Platform.Sdl3 onward), open upstream. Pinned centrally to the `11.0.0` GA release since #82: in CI run 45724049611 (PR #137, head `e2bc6d5`) the smoke harness rented and returned a builder from BRUTAL's `StringBuilderPool<char>.Shared` and printed `Microsoft.Extensions.ObjectPool 11.0.0.0 / 11.0.0+297acf930fb0f5c07fd4e51d78e521b4ad2e5d1f, PROBE OK` in its JIT and NativeAOT runs on both `ubuntu-24.04` (linux-x64) and `windows-2025` (win-x64), and locally on Windows 11 (JIT and win-x64 NativeAOT, RTX 2070 SUPER); macOS not run ([ADR-0015](adr/0015-tested-platforms-windows-linux.md)). An architecture test (`PackageClosureRule`) fails if Core, Platform, Graphics or World resolve `Ahwoo.Brutal.Strings` or `Microsoft.Extensions.ObjectPool`. Binding gaps: open, worked around per backend |
